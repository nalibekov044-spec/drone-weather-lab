# Drone Weather Lab 0.85 Beta

**[English documentation](README.en.md)** · **[Online simulator](https://nalibekov044-spec.github.io/drone-weather-lab/)**

Симулятор для изучения того, как ветер, погода и параметры дрона влияют на его поведение. Можно менять массу, винты и двигатели, наблюдать удержание точки, исследовать численное поле воздуха и сравнивать две конфигурации при одинаковой погоде.

## Как запустить

**[Онлайн симулятор](https://nalibekov044-spec.github.io/drone-weather-lab/)** · **[Скачать файлы релиза](https://github.com/nalibekov044-spec/drone-weather-lab/releases)**

Если сайт уже опубликован, просто открой первую ссылку. Устанавливать программы и скачивать исходники не нужно. Эти ссылки начнут показывать новую версию после её загрузки на GitHub и включения Pages.

Для запуска из файла:

1. Скачай `Drone-Weather-Lab-0.85-Beta.html` из релиза. Если скачал ZIP, сначала распакуй его.
2. Открой HTML двойным щелчком. Если компьютер спрашивает, чем открыть, выбери браузер.
3. Симулятор работает без Python, Node.js, терминала и интернета. Для внешних ссылок на документацию интернет нужен.

На Windows `Start.cmd` открывает тот же файл. Содержимое `dist` предназначено для публикации и разработки; для обычного запуска выбирай HTML в корне.

Сборка для Windows подготовлена в GitHub Actions. После успешного задания Build release downloads к релизу прикрепляется `Drone-Weather-Lab-0.85-Beta.exe`. Он содержит этот же HTML, сохраняет его в локальную папку приложения и открывает в браузере. Установка Python не требуется. Запуск использует .NET Framework 4 и ассоциацию HTML файлов в Windows. Исполняемый файл ещё не был собран и проверен в Windows при подготовке этого архива; подпись издателя не настроена. HTML вариант не зависит от этой сборки.

## Первый эксперимент

Выбери русский язык и метрические единицы. Язык и система единиц меняются независимо и сохраняются на твоём устройстве.

1. Оставь камерный квадрокоптер. В режиме «Полёт» увеличь средний ветер с 6 до 12 м/с. Посмотри на смещение, наклон и запас тяги. Поверни ветер и проследи за стрелками сил.
2. Открой «Графики». Выбери скорость ветра и наклон или запас тяги. Остальные параметры при построении кривой остаются неизменными.
3. Открой «Обтекание». Начни с быстрой сетки. Дождись расчёта, поверни сцену, переключи скорость, давление и завихрение. В диагностике посмотри на невязку и размер ячейки.
4. Включи «Расчётная геометрия». Точки показывают центры твёрдых ячеек решателя. На грубой сетке тонкие лучи или шасси могут исчезнуть, хотя в 3D модели они видны.
5. Открой «Сравнение» и сохрани A. Измени нагрузку или выбери другой дрон, затем сохрани B. Для обоих вариантов используется погода из A и исправные моторы. Импортированный CAD и отдельные RPM двигателей в сравнение не входят.

## Что изменилось в 0.85 Beta

Запуск из одного HTML файла без локального сервера. Внутри находятся оформление, переводы, 3D сцена и оба фоновых обработчика. GitHub Pages также предлагает этот файл для скачивания. Отдельное задание Actions собирает Windows запускатель и проверяет, что встроенный HTML извлекается без изменений.

У моторов появились корпусные кольца, вентиляция и ступицы. Добавлены элементы камеры, крепления батареи, навигационный модуль и световые полосы на лучах. Лопасти имеют объём, закрутку профиля и сохранённую фазу вращения. Их геометрия загружается в GPU один раз при изменении винта. При остановке мотора лопасть сохраняет угол. Сглаживание нормалей теперь учитывает конкретную деталь, включая повёрнутые эллипсоиды и цилиндры.

Smagorinsky LES добавляет локальную вихревую вязкость по неравновесному тензору напряжений. Источник крутящего момента диска задаётся через Q = P / ω. Сила и момент нормируются по ячейкам; противоположное вращение соседних дисков учтено. LES и закрутку можно отключить отдельно.

Остановка CFD проверяет изменение скорости и силы. В диагностике видны обе невязки, баланс массового расхода, средняя сила последних десяти измерений и максимальная добавочная вязкость. Доступная тяга в CFD учитывает тепловое ограничение моторов с округлением до 10%, чтобы расчёт не перезапускался каждый кадр.

## Как читать параметры и результаты

| Параметр или результат | Значение |
| --- | --- |
| Масса корпуса и нагрузка | Общая масса определяет вес и необходимую тягу |
| Диагональ рамы | Расстояние между противоположными моторами |
| Диаметр винта | Влияет на площадь диска, тягу, мощность и скорость струи |
| Шаг винта | Теоретическое продвижение за оборот, используется при оценке коэффициентов |
| RPM | Обороты в минуту; в формулах переводятся в обороты в секунду |
| Мощность мотора | Электрический предел одного двигателя с ESC; мощность на валу ниже |
| Запас тяги | Доступная тяга сверх требуемой; отрицательное значение означает нехватку |
| Наклон | Угол, необходимый для компенсации горизонтального ветра |
| Время полёта | Энергия батареи, делённая на оценочную мощность, если удержание точки возможно |
| Downwash | Идеальная скорость вниз у дисков, отличается от измерения скорости в поле CFD |
| Давление CFD | Относительно опорной плотности, а не атмосферное давление |
| Завихрение | Локальное вращение поля скорости в с⁻¹ |
| Невязка | Относительное изменение скорости за 20 итераций |
| Сила на твёрдых телах | Мгновенные компоненты X, Y, Z, включая дополнительные препятствия |

Метрическая и имперская системы меняют отображение. Внутренние значения сохраняют исходные единицы. Рядом с ползунками можно вводить точные числа с точкой или запятой. Неверный ввод оставляет последнее допустимое значение. Количество линий должно быть целым.

Погода включает средний ветер, направление, порывы и их частоту, условную интенсивность нерегулярных порывов, вертикальный поток, дождь, температуру, влажность, высоту, давление и обледенение. В полёте вектор ветра меняется плавно. CFD использует средний ветер и неподвижную геометрию, без нового расчёта на каждом порыве. Изменение средних условий или геометрии ставит новый расчёт в очередь, интерфейс остаётся доступным.

## Конструктор и CAD

В режиме «Свой дрон» настраиваются длина, ширина и высота корпуса, его форма, длина и толщина лучей, растяжение рамы, расположение роторов и размеры моторов. Конструктор показывает объём корпуса и зазор между винтами. Пересечение винтов вызывает предупреждение. Геометрия не определяет массу и лобовую площадь автоматически, их нужно указать отдельно.

«Сохранить настройки» экспортирует JSON. Загрузка проверяет все параметры перед применением. CAD файл, повреждения моторов и индивидуальные RPM не сохраняются. STL экспортируется в миллиметрах, с осью Y вверх. Детали пересекаются: перед производством объедини и проверь их в CAD. Это эскиз, а не готовая конструкция.

Из Fusion, SolidWorks, FreeCAD или Blender экспортируй STL или OBJ. STEP и IGES сначала нужно преобразовать. Ограничение составляет 16 МБ и 40 000 треугольников. Укажи реальный наибольший размер и вертикальную ось. Файлы обрабатываются локально и не отправляются на сервер.

Перед включением импортированной сетки в CFD проверь её замкнутость, масштаб и совпадение центров винтов. Незамкнутую сетку можно показать, но нельзя использовать как твёрдый корпус. Положение роторов берётся из выбранной рамы, автоматически из CAD оно не определяется. Тонкие детали могут исчезнуть при переводе в ячейки. Посмотри на расчётную геометрию, чтобы это проверить.

## Моторы и клавиши

Тепло накапливается и уходит постепенно. После 95 °C начинается ограничение мощности, которое может исчезнуть при охлаждении. Долгая перегрузка при высокой температуре расходует ресурс без самостоятельного восстановления. Тяжёлый накопленный перегрев может вызвать условные дым и огонь. В модели нет измеренных тепловых данных твоего двигателя, она не предсказывает настоящий пожар. Команда RPM также используется как отдельный сценарий перегрузки, а не измеренный ток обмоток при зависании.

| Клавиша | Действие |
| --- | --- |
| Пробел | Пауза или продолжение полёта и анимации частиц |
| F | Восстановить температуру, ресурс и состояние моторов |
| R | Начать полёт заново, сохранив параметры и состояние моторов |
| G | Графики |
| C | Обтекание |
| 1 | Полёт |
| ? | Показать клавиши |

Во время ввода клавиши не срабатывают. «Сбросить» возвращает исходную конфигурацию.

## Как устроены расчёты

Плотность воздуха определяется температурой, давлением и влажностью. Автоматическое давление берётся из стандартной барометрической атмосферы. Основные зависимости винтов:

$$T = C_T\rho n^2D^4, \qquad P_{shaft} = C_P\rho n^3D^5$$

T измеряется в Н, P в Вт, ρ в кг/м³, n в оборотах в секунду, D в метрах. Cₜ и Cₚ безразмерные. Оценочные коэффициенты можно заменить данными испытаний своего винта. Электрическая мощность учитывает КПД и дополнительное потребление.

Сила ветра оценивается по формуле:

$$F = \frac{1}{2}\rho C_D A V^2$$

C𝒹 обозначает коэффициент сопротивления, A площадь поперёк ветра в м², V скорость в м/с. Модель полёта использует условный контроллер положения, ограничения моторов и просадку напряжения. Сила на поверхности из CFD рассчитывается отдельно.

Решатель CFD использует D3Q19 LBM, столкновения TRT или BGK, источник силы Guo, неподвижные твёрдые границы bounce-back и диски винтов с источником импульса. Линии тока интегрируются методом RK4 по численному полю. Частицы движутся по локальному времени прохождения. Скорость просмотра меняет только анимацию. Больше линий улучшает видимость, но не делает сетку точнее.

Момент винта оценивается по $Q=P_{shaft}/\omega$, где $\omega=2\pi n$. Мощность и обороты приводятся к оценочному режиму диска. Тангенциальный источник сохраняет заданный момент вокруг оси Y и не добавляет суммарную боковую силу.

Для LES используется $\nu_t=(C_s\Delta)^2|S|$ с $C_s=0{,}12$. Локальное время релаксации рассчитывается из неравновесного тензора напряжений $\Pi$:

$$\tau_{eff}=\frac{\tau_0+\sqrt{\tau_0^2+18C_s^2\sqrt{2\Pi:\Pi}/\rho}}{2}$$

Здесь значения тензора и плотности в единицах решётки; $\Pi:\Pi$ означает сумму квадратов всех компонентов с учётом симметрии. Тензор включает поправку на источник Guo. Этот расчёт добавляет вязкость поверх базовой численной вязкости, а не заменяет её физической вязкостью воздуха. У стенок отдельной модели демпфирования нет.

Массовый расход через границы суммируется как $\sum\rho u_n\Delta A$ с трапецеидальными весами на краях граней. При установлении ненулевой баланс может соответствовать изменению массы внутри области. Это диагностический показатель, а не самостоятельное доказательство точности.

## Точность и проверки

Проверки этой версии записаны в `verification-v085.json`. Для затухания периодической сдвиговой волны на 32 ячейках за 200 шагов ошибка амплитуды составила 0,36% у BGK и 0,17% у TRT относительно аналитического решения. В тесте источника получены 3,99999996 Н при заданных 4 Н и 0,0599999999 Н·м при заданных 0,06 Н·м; боковой результирующий импульс практически нулевой.

Проверены однородный поток с LES, баланс на границах, направление и симметрия сопротивления сферы, конечность поля дрона с моментами винтов, сохранение массы и импульса, продолжение фонового расчёта, перевод, точный ввод и интеграция интерфейса. Шейдеры компилируются в Mesa GLES. Модели визуально проверены на отдельном GPU рендере. Полного запуска страницы в обычном браузере и запуска Windows программы здесь не было.

Сфера с LES на быстрой сетке достигла критерия изменения скорости и силы; дисбаланс расхода составил около 0,007%. Тест дрона на 200 шагах ещё не сошёлся и в отчёте помечен соответствующим образом. У него пиковое число Маха решётки около 0,24, поэтому сжимаемость остаётся заметным ограничением. `verification-v08.json` сохранён как предыдущая проверка двух сеток; независимость от сетки для 0.85 Beta не установлена.

Численная вязкость повышена, физическое и расчётное Re отличаются. Сетки содержат около 13, 31 и 61 тысячи ячеек. LES и момент диска не разрешают отдельные лопасти, пограничный слой и реальные вихри за концами лопастей. Дождь, лёд и деградация моторов используют оценочные коэффициенты. Сравнения с аэродинамической трубой или реальным дроном пока нет.

Для проверок нужен Node.js с поддержкой `vm.SourceTextModule`:

```sh
node --experimental-vm-modules scripts/verify.mjs
node --experimental-vm-modules scripts/verify-v06.mjs
node --experimental-vm-modules scripts/verify-v07.mjs
node --experimental-vm-modules scripts/verify-v085.mjs
node --experimental-vm-modules scripts/verify-ui.mjs
node --experimental-vm-modules scripts/verify-ui.mjs --offline
node scripts/verify-standalone.mjs
```

`verify-v085.mjs` пересоздаёт численный отчёт. Время выполнения зависит от компьютера.

## Выпуск на GitHub

1. Загрузи содержимое архива в корень репозитория, включая папки `.github`, `desktop`, `docs`, `dist` и `scripts`, оба README и HTML файл. Не создавай дополнительную папку с номером версии.
2. Для сайта открой Settings, затем Pages и выбери GitHub Actions. В Actions дождись зелёного Deploy GitHub Pages. Ссылку бери из Settings, Pages и проверь без входа в аккаунт.
3. Чтобы собрать скачиваемые файлы, открой Actions, выбери Build release downloads и нажми Run workflow. После успешной сборки забери файл из Artifacts.
4. Для релиза с автоматическими вложениями создай тег `v0.85.0-beta`. Можно открыть Releases, Draft a new release, создать этот тег из `main` и отметить Set as a pre-release. После публикации задание соберёт HTML, ZIP и `.exe` и прикрепит их к релизу.

Текст для описания релиза находится в `RELEASE.en.md`. Готового `.exe` в исходном архиве нет: его собирает Windows задание. Если сборка не прошла, в Actions есть журнал; HTML можно использовать независимо.

Для изменений в коде пересобирай единый файл командой `node scripts/build-standalone.mjs`. Это требуется только разработчику. Pages и релиз делают такую сборку автоматически. Для работы с отдельными модулями можно запускать `python scripts/start.py`; посетителю это не нужно.

## Если что-то не работает

| Проблема | Что проверить |
| --- | --- |
| Пустая страница при открытии HTML | Открой файл в корне, а не `dist/index.html`, через браузер |
| Start.cmd не открыл симулятор | Открой HTML файл напрямую через браузер |
| Расчёт медленный | Начни с быстрой сетки и эскиза; плотность линий уменьшается отдельно |
| WebGL недоступен | Используется Canvas; проверь обновления браузера и видеодрайвера |
| Отрицательный запас тяги | Проверь массу, винты, RPM и предел мощности |
| Нет времени полёта | При выбранных допущениях удержание точки невозможно |
| CFD ещё не сошёлся | Продолжи расчёт и проверь невязку, число Маха и плотность |
| CAD нельзя включить в CFD | Исправь сетку, размер и ось вверх, оставь её внутри области |
